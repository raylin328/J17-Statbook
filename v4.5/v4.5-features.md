# J17 Stat Book v4.5 — Feature List

## Core Features for v4.5

### 1. Substitution Tracking
- **Lineup picker at game start:** Select 5 players (or fewer for non-standard games)
- **Substitution UI:** "Who's going out? Who's coming in?"
- **Automatic lineup management:** App creates new lineup entry when a sub happens
- **Bench display:** Shows current players on court, who's available to sub in
- **Player shifts stored:** Each in/out is logged with time (period + minute)

### 2. Minutes Played
- **Auto-calculated from shifts:** No manual entry needed
- **Displayed in box score:** Shows `minutes:seconds` format (e.g., 28:30)
- **Per-minute stats:** Points/minute, assists/minute, etc. in box score view
- **Playing time tracking:** Identifies who played most, least, DNP (did not play)

### 3. Possessions (Foundation)
- **Possession counter:** App tracks possession number (1st possession, 2nd, etc.)
- **Start/end times:** When possession began and ended (period + minute)
- **Possession duration:** Auto-calculated in seconds
- **Possession result:** "Score" (2P/3P/FT), "Turnover", "Defensive rebound", "Period end"
- **Points scored:** 0, 1, 2, or 3 (null if no score)

### 4. Possession Players (Who was involved)
- **Possession roles:** Handler (started with ball), Passer, Shooter, Cutter, Screener, Rebounder
- **Tag players after each event:** "Who touched this possession?"
- **Multiple roles per player:** Same possession can list Marc as "handler" and "passer"
- **Possession flow:** Reconstruct the flow of play from tags

### 5. Non-standard Lineups
- **Support 3v3, 4v4, or any combo:** Don't force 5 players
- **Game type picker:** "5v5", "4v4", "3v3" at start
- **Lineup display adapts:** Bench shows 1-2 available, not "missing 2 players"
- **Subs work at any size:** If playing 3v3, can swap 1 of the 3

### 6. Coach Attribution (Practice Sessions)
- **Coach picker in practice:** Dropdown to select which coach ran this practice
- **Training regimen selector:** "Which training approach did we use today?"
- **Attendance tracking:** Mark who attended, who was DNP (injured, sick, personal)
- **Export includes coach:** CSVs include coach name and regimen

### 7. Improved Error Handling & UX
- **Confirm before clearing all data:** "This will delete everything. Export first?"
- **Undo last sub:** Button to reverse the most recent substitution
- **Possession timer display:** Shows elapsed time for current possession
- **Better game clock display:** Larger, more visible, shows quarter + time left

## Clear All Players Feature

### Function: `clearAllPlayers(exportFirst)`

**Location:** Players tab, new button **"Clear All Players"**

**Behavior:**

1. User clicks **"Clear All Players"**
2. Modal appears:
   ```
   ⚠ Delete all players?
   
   This cannot be undone. Consider exporting your data first.
   
   [Export to CSV] [Cancel] [Delete All]
   ```

3. If user clicks **"Export to CSV":**
   - Downloads `players_backup.csv` with all current players
   - Modal stays open
   - User can then click **"Delete All"**

4. If user clicks **"Delete All":**
   - All players removed from `S.players`
   - Data saved
   - Page refreshes
   - "All players deleted" confirmation toast

5. If user clicks **"Cancel":**
   - Modal closes
   - Nothing happens

**Code:**

```javascript
function clearAllPlayers() {
  if (!confirm("Delete all players? This cannot be undone. Consider exporting first.")) {
    return;
  }
  
  var shouldExport = confirm("Export players to CSV before deleting?");
  
  if (shouldExport) {
    // Export first
    var csv = "id,name,jersey number,desc,aliases,notes\n";
    S.players.forEach(function(p) {
      var row = [
        p.id,
        p.name || "",
        p.num || "",
        p.desc || "",
        (p.aliases || []).join(";"),
        p.notes || ""
      ];
      csv += toCSVLine(row) + "\n";
    });
    
    var blob = new Blob([csv], { type: "text/csv" });
    var url = URL.createObjectURL(blob);
    var a = document.createElement("a");
    a.href = url;
    a.download = "players_backup_" + new Date().toISOString().split("T")[0] + ".csv";
    document.body.appendChild(a);
    a.click();
    document.body.removeChild(a);
    URL.revokeObjectURL(url);
    
    toast("Players exported. Click again to delete.");
    return;
  }
  
  // Delete all players
  S.players = [];
  save();
  render();
  toast("All players deleted");
}
```

**UI Button (in Players tab):**

```javascript
// Add to Players tab view
var clearBtn = el("button", {
  cls: "btn danger",
  text: "🗑 Clear All Players",
  on: {
    click: clearAllPlayers
  }
});
```

## Database Schema Changes (for eventual backend)

Once you add a database backend, these tables store this data:

```sql
-- game_lineups: one row per lineup change
CREATE TABLE game_lineups (
  id UUID, game_id UUID, lineup_number INTEGER,
  player_ids UUID[], num_players INTEGER,
  start_period INTEGER, start_minute INTEGER,
  end_period INTEGER, end_minute INTEGER
);

-- player_shifts: one row per player in/out
CREATE TABLE player_shifts (
  id UUID, game_id UUID, player_id UUID,
  shift_type VARCHAR (on/off),
  period INTEGER, minute INTEGER,
  reason VARCHAR (sub_in/sub_out/game_start/game_end)
);

-- game_possessions: one row per possession
CREATE TABLE game_possessions (
  id UUID, game_id UUID, possession_number INTEGER,
  start_period INTEGER, start_minute INTEGER,
  end_period INTEGER, end_minute INTEGER,
  result VARCHAR (score/turnover/defensive_rebound),
  points_scored INTEGER
);

-- possession_players: one row per player per role per possession
CREATE TABLE possession_players (
  id UUID, possession_id UUID, player_id UUID,
  role VARCHAR (handler/passer/shooter/cutter/screener/rebounder)
);

-- practice_sessions: track coach and regimen
CREATE TABLE practice_sessions (
  id UUID, coach_id UUID, regimen_id UUID,
  session_date DATE, location VARCHAR
);

-- practice_attendees: track who showed up
CREATE TABLE practice_attendees (
  id UUID, session_id UUID, player_id UUID,
  attended BOOLEAN, dnp_reason VARCHAR
);
```
